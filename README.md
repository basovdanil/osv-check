# osv-check

[![tests](https://github.com/basovdanil/osv-check/actions/workflows/tests.yml/badge.svg)](https://github.com/basovdanil/osv-check/actions/workflows/tests.yml)

**[English](README.en.md)** · [Русский](README.md)

Проверка оборотно-сальдовой ведомости из 1С до того, как цифры ушли в отчёт.

Скрипт читает CSV-выгрузку, пересчитывает каждую строку и итоги и говорит, где
арифметика не сходится и где остаток стоит на неправильной стороне счёта.

Только стандартная библиотека Python 3.8+. Ни pandas, ни установки: файл
запускается на машине, где есть один python.

Разбор кейса на сайте: https://basovdanil.github.io/portfolio/case-osv/case-osv.html

## Пайплайн

```text
balance.csv ──▶ разбор и нормализация ──▶ проверки ──────────▶ консоль / --json
                колонки, числовые суммы   сальдо, обороты,     exit 0 — чисто
                                          красное сальдо,     exit 4 — есть находки
                                          итоги Дт и Кт
```

## Что проверяет

| Код | Что значит |
| --- | --- |
| `row_mismatch` | сальдо строки не равно «начальный остаток + обороты» |
| `red_balance` | отрицательный остаток там, где его быть не может: минус по кассе, складу, расчётному счёту |
| `negative_turnover` | отрицательный оборот: обычно значит, что дебет и кредит перепутаны местами |
| `unknown_type` | тип счёта не из списка `активный`, `пассивный`, `активно-пассивный` |
| `totals_open` | дебетовое и кредитовое сальдо на начало не равны между собой |
| `totals_turn` | дебетовый и кредитовый оборот не равны между собой |
| `totals_close` | дебетовое и кредитовое сальдо на конец не равны между собой |

Проверка «красного сальдо» смотрит на знак остатка: на активном счёте
кредитовый остаток записан как минус в дебетовой колонке, на пассивном наоборот.
Расхождение больше копейки считается ошибкой, поэтому округление в выгрузке
не даёт ложных срабатываний.

## Формат файла

CSV с заголовком, разделитель `;` или `,`, кодировка UTF-8 или windows-1251.
Колонки, порядок любой:

```
account,name,type,open_debit,open_credit,turn_debit,turn_credit,close_debit,close_credit
```

Числа понимаются в формате 1С: `1 234 567,89`, неразрывный пробел как разделитель
разрядов, минус в скобках `(1 000)`, пустая ячейка и прочерк как ноль.

## Запуск

```
python osv_check.py баланс.csv
python osv_check.py баланс.csv --json
python osv_check.py баланс.csv --expect ожидаемые.json
```

`--json` печатает находки и итоги объектом, без цвета и прогресса.
`--expect` сравнивает набор находок с файлом-эталоном и отвечает кодом `0`,
если наборы совпали: это защита от того, что проверка молча перестала ловить
ошибку после правки.

```
python osv_check.py demo/balance.csv
python osv_check.py demo/balance.csv --expect demo/expected.json
```

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | находок нет или набор совпал с `--expect` |
| `2` | неверные аргументы |
| `3` | файл не читается, нет нужных колонок или битый `--expect` |
| `4` | есть находки или набор не совпал с ожидаемым |

## Тесты

```
python -m unittest discover -s tests
```

13 тестов: разбор чисел из 1С, арифметика строк, красное сальдо на активном и
пассивном счёте, отрицательный оборот, несходящиеся итоги, коды возврата CLI
и совпадение с `--expect`.

## Данные

`demo/balance.csv` — синтетическая ведомость на 16 вымышленных счетов. Ни одного
реального контрагента, оборота или остатка. Ошибки в ней расставлены намеренно,
по одной на каждый тип находки.

## Границы

Скрипт проверяет арифметику и знаки, а не смысл проводок. Он не знает, должна ли
была эта сумма попасть на этот счёт, и не заменяет сверку с первичными документами.
Формат рассчитан на выгрузку «ОСВ по счёту» и не разбирает многоуровневые
группировки с промежуточными итогами.
